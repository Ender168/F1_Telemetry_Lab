# Персональные подсказки, версия 0.10.15

В выбранный ERS JSON добавляется необязательный блок `track_guidance`.
Подсказки используют только телеметрию игрока и работают при ERS Off, DryRun,
Live и при восстановлении ERS. Они не управляют педалями или рулём.
Профиль выбирается теми же фильтрами трассы, сессии, шин и погоды, что и ERS.
Старые JSON без этого блока продолжают работать.

## Пример структуры

Все координаты и скорости ниже условные, это НЕ калибровка Каталонии.
Сначала замените их данными своих успешных кругов, затем включите `enabled`.
Фрагмент добавляется внутрь существующего профиля, не является полным ERS JSON.

```json
"track_guidance": {
  "enabled": false,
  "suppress_on_pit_lap": true,
  "cues": [
    {
      "id": "t1-note",
      "kind": "info",
      "text": "T1: избегай внутреннего поребрика",
      "start_m": 400,
      "end_m": 650
    },
    {
      "id": "t1-brake",
      "kind": "brake",
      "text": "T1: торможение за 150 м до поворота",
      "start_m": 650,
      "end_m": 890,
      "target_m": 850,
      "tolerance_m": 15,
      "brake_threshold": 0.05
    },
    {
      "id": "t1-entry",
      "kind": "speed",
      "text": "T1: на входе 115-125 км/ч",
      "start_m": 891,
      "end_m": 1050,
      "target_m": 1000,
      "tolerance_m": 20,
      "minimum_speed_kph": 115,
      "maximum_speed_kph": 125
    }
  ]
}
```

`start_m`, `end_m`, `target_m` задаются в метрах UDP lap distance от линии старта.
Например, при опорной точке поворота 1000 м торможение за 150 м даёт `target_m=850`.
Это не автоматическое распознавание табличек на трассе.
Окно может пересекать линию старта: `start_m > end_m`.
Точка цели и её допуск должны полностью находиться внутри окна показа.
Текст до 160 символов, рекомендуется одна короткая строка.

## Оценка и цвета

- `info`: голубой текст, без оценки выполнения.
- До цели: голубой, расстояние до точки.
- В диапазоне `target_m ± tolerance_m`: жёлтый призыв к действию.
- `brake`: зелёный только при переходе педали снизу вверх через `brake_threshold`
  внутри допуска; раннее или позднее начало даёт красный результат.
- `speed`: скорость оценивается при пересечении `target_m`, с линейной интерполяцией
  между соседними отсчётами. Зелёный означает попадание в заданный диапазон.
  Достижение скорости раньше точки не засчитывается. `tolerance_m` здесь задаёт
  только начало жёлтой индикации, не разрешает оценку в произвольном месте.
- Результат сохраняется до конца окна. Пропуск данных более 250 мс или скачок
  расстояния более 100 м прекращает оценку; без наблюдения контрольной точки
  выводится серый статус «Недостаточно данных для оценки».

Одна плашка показывает одну подсказку. Измеримые действия выше информационных;
далее выбирается больший `priority` (по умолчанию 0), при равенстве ID по алфавиту.
Все видимые действия оцениваются, даже если на плашке показано другое.
Лучше задавать непересекающиеся окна: сброс газа в LIFT & COAST, затем торможение,
затем скорость на входе. Два оверлея независимы, их окна согласуются в JSON.

Плашка «ПОДСКАЗКИ ТРАССЫ» перемещается, масштабируется и скрывается редактором
оверлея. Обновление интерфейса каждые 50 мс, оценка по поступающей телеметрии.
Пауза, пит-лейн, SC/VSC, устаревшие данные и подтверждённый Flashback сбрасывают
оценку. `suppress_on_pit_lap` скрывает подсказки при активной отметке pitLapBurn.
Невалидный блок отклоняет весь профиль с предупреждением, как `lift_coast`.

## Автовосстановление ERS

После исчерпания попыток подтверждения переключения приложение отпускает
свои клавиши, очищает ожидающую команду и ждёт 3 секунды. Повторные сбои дают
паузы 6, 12, 24, затем 30 секунд. После подтверждённого переключения задержка
следующего сбоя снова 3 секунды. Запись SQLite продолжается без перезапуска.

Возобновление требует актуальных данных и выполнения обычных условий ERS.
Команда рассчитывается заново из фактического режима и текущей позиции.
Механизм отправки дополнительно проверяет, что окно F1 активно.
Состояние стратегии, once_per_lap и отметка пит-круга не сбрасываются самим
восстановлением; обычные сбросы при смене сессии/шин и Flashback сохраняются.
F12 и ошибки отправки/отпускания клавиш остаются блокировками до новой записи.
Журнал содержит `feedback-timeout-recovering` и `input-recovery-resumed`.
В статусе Recovering указывается неудавшийся переход и обратный отсчёт.
