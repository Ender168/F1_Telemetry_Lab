# F1 Telemetry Lab v0.9.1

## Зачем нужен этот выпуск

Live-тест `China_Race_20260830_203202` показал, что v0.9.0 рассчитывала правильные цели ERS и вызывала Windows `SendInput`, но F1 25 не подтверждала изменение режима. Старый backend отправлял virtual-key key-down и key-up одним вызовом без времени удержания. Короткие правила также могли ошибочно получить `telemetry-confirmed`, когда цель возвращалась к Medium до появления ожидаемого режима.

## Новый Windows-ввод

- F7/F8 преобразуются в аппаратный scan-код через `MapVirtualKey`.
- Key-down и key-up отправляются раздельно.
- Клавиша удерживается 80 мс, чтобы игра увидела нажатое состояние хотя бы в нескольких кадрах.
- Отпускание выполняется из последовательного UDP writer pipeline и не блокирует receive loop.
- Stop, F12 или input fault принудительно отпускают удерживаемую клавишу.

## Подтверждение по UDP

Переход Medium -> Boost требует увидеть каждый следующий режим из Packet 7. Подтверждение теперь относится к ожидаемому промежуточному состоянию, а не просто к текущей цели профиля. Если короткая зона завершилась раньше, журнал получает `feedback-superseded`, а не ложное `telemetry-confirmed`.

## Что проверяет следующий тест

v0.9.1 остаётся диагностическим прототипом. Успешный результат подтверждается только строками `Pressed ... scan-code`, `Released ... scan-code` и последующим `telemetry-confirmed` в `ers_control_log.csv`, а также видимым изменением ERS Mode в игре. Если F1 25 по-прежнему не принимает ввод, дальнейший путь требует эмуляции контроллера вместо Windows keyboard injection.
