# F1 Telemetry Lab v0.9.0

## Результат

v0.9.0 добавляет первый прототип автоматического управления стандартным ERS поверх существующего UDP recorder. Контроллер не создаёт отдельный канал телеметрии и не мешает receive loop: решения выполняются последовательно в writer pipeline после получения неизменённого пакета.

Архитектура рассчитана на постепенное наполнение чемпионата. Каждая трасса получает отдельный JSON-профиль в `<root>/ers_profiles/`. Файлы читаются при старте записи, поэтому новый алгоритм или настройка существующего не требуют пересборки приложения.

## Режимы работы

| Режим | Назначение |
|---|---|
| Off | Полностью отключить ERS controller |
| Dry-run | Рассчитать и записать решения без отправки клавиш |
| Live | Выполнять подтверждаемые переходы стандартного ERS через F7/F8 |

Dry-run включён по умолчанию. Переключатель блокируется на время записи, чтобы режим сессии был однозначным.

## Первый алгоритм: China R03

Профиль `china-race-r03-v1` переносит выводы последнего разбора Китая в консервативные правила:

| Участок | Нормальный план |
|---|---|
| T16 -> T1 | Medium; короткий Boost только в бою или при высоком заряде |
| T1 -> T4 | Medium; None при активном восстановлении |
| T4 -> T6 | Medium; короткий Boost только в бою или при высоком заряде |
| T6 -> T10 | Medium; None при низком заряде |
| T10 -> T13 | Medium; None для создания резерва перед главным разгоном |
| T13 -> первая часть прямой T14 | Один основной ограниченный Boost |
| T14 -> T16 | Medium; None при низком заряде |

Целевой рабочий диапазон батареи задаётся порогами профиля. В первой версии восстановление включается при 35% и выключается после 45%, высокий резерв начинается с 65%, критическая защита включается на 12%. В интерфейсе и журнале участки подписаны поворотами; метровые координаты остаются внутренними триггерами JSON.

## Feedback control

UDP предоставляет текущее состояние, но не команду изменения ERS. Поэтому Live использует назначенные в игре клавиши:

1. Контроллер сравнивает фактический `ersDeployMode` с целью профиля.
2. Отправляется только одно нажатие Increase или Decrease.
3. Следующее нажатие запрещено до подтверждения ожидаемого режима из Packet 7.
4. После таймаута выполняются ограниченные повторы.
5. Если подтверждение не приходит, Live-ввод блокируется до следующей записи.

Такой переход корректно проходит промежуточный Hotlap между Medium и Boost и не предполагает, что игра приняла команду.

## Safety gate

Live никогда не отправляет ввод, если выполняется хотя бы одно условие:

- session является сетевой;
- игровой ERS Assist включён или его флаг ещё не получен;
- окно F1 25 не находится на переднем плане;
- игра на паузе или recorder получает network pause;
- активен spectator mode, Safety Car, VSC или formation lap;
- игрок находится в питах или не на активном гоночном круге;
- player telemetry или session safety state устарели;
- длина трассы заметно отличается от профиля;
- профиль помечен `dry_only`, а погода дождевая;
- скорость ниже минимальной границы профиля;
- F12 был нажат в текущей записи;
- игра не подтверждает отправленные переключения.

Новый Overtake Mode 2026 из Packet 16 намеренно не изменяется и остаётся ручным.

## Аудит и analysis pack

При выборе профиля в папку сессии записывается `ers_profile_used.json`. Он содержит точную конфигурацию, режим работы и назначенные клавиши. `ers_control_log.csv` фиксирует смены решений, причины safety block, отправленные команды и подтверждения телеметрии.

Оба файла автоматически попадают в analysis ZIP. `analysis_pack_version` повышен до 2; database schema остаётся версии 5, поскольку новые данные не требуют миграции SQLite.

## Добавление следующей трассы

Кнопка `Open ERS profiles` открывает каталог профилей и локальную инструкцию. Для нового этапа достаточно скопировать China JSON, заменить идентификаторы трассы и сессии, задать участки и правила, затем проверить алгоритм в Dry-run. При нескольких совпадениях используется `selection_priority`.

## Проверка перед первым Live-заездом

1. Установить UDP Format 2026 и UDP Send Rate 60 Hz.
2. Выключить ERS Assist.
3. Назначить Decrease ERS Deploy Mode на F7, Increase ERS Deploy Mode на F8.
4. Провести короткую офлайн-сессию в Dry-run.
5. Проверить подписи участков, цели и заряд в `ers_control_log.csv`.
6. Проверить F12 и возврат управления вручную.
7. Только затем провести короткую офлайн-сессию в Live.

Live-инъекция требует практической проверки в самой F1 25 на Windows. Автоматические тесты покрывают parser offsets, принятие решений, гистерезис, переход через линию старта, hard block онлайна, ERS Assist и аварийную блокировку.
